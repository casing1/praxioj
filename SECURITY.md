# Security boundaries

PraxiOJ Milestone 3 is an independent personal open-source development preview. It is not approved for public deployment. `PRAXIOJ_ENV` accepts only `development` and `test`; native servers must bind to loopback. Compose publishes only API/web loopback ports and leaves PostgreSQL unpublished unless the optional native override is used. API and worker containers can initiate outbound requests. Container networking and logical files are not contestant sandboxes.

## System and trust boundaries

The Framework defines manifests, providers, tools, traces and deterministic evaluation. The Platform stores accounts, jobs and participant data. Participants and model output are untrusted. Problem authors may publish declarative manifests only for problems they manage. A local operator controls provider URLs/credentials, role assignment and deployment. Database/host administrators are trusted with storage access; the event hash chain does not protect against an administrator rewriting both evidence and checkpoints.

## Implemented controls and invariants

- Passwords use Argon2id (64 MiB, three iterations, parallelism four) through argon2-cffi. Random login and CSRF tokens are stored as hashes. HttpOnly, SameSite=Strict cookies have bounded expiry; Secure is configurable for local HTTPS. Logout and role changes revoke login records. There is no default administrator password or automatic elevation of old browser identities.
- Registration/login require an allowed Origin. Authenticated mutations require a synchronizer CSRF header; cross-site requests, unexpected hosts, non-JSON writes and oversized bodies are rejected. Authentication attempts have shared PostgreSQL rate buckets; forwarded client-IP headers are not trusted.
- Backend checks enforce administrator/author/participant roles and resource ownership. Other participants cannot read or mutate sessions, conversations, runs, logical files, submissions, evaluations or traces. Author review is scoped to owned problems and exposes a minimal assessment projection. Administrator audit endpoints exclude raw participant content and credentials.
- User-first mutation locking serializes account erasure with new private writes. Session locks serialize trace sequence allocation and workspace mutation. Immutable problem versions and submissions carry content digests; new events carry a hash chain and persisted checkpoint. Legacy events are explicitly unverified.
- API transactions enqueue durable jobs with request UUIDs. Workers claim with PostgreSQL row locks and SKIP LOCKED, renew leases and check token/fence/expiry before every result or tool mutation. Cancellation revokes ownership before acknowledgement. Expired jobs fail without automatically repeating possibly billed provider calls. Exactly-once external execution is not guaranteed.
- Provider endpoints/keys remain server-side. Participants select configured profiles and problem-permitted models. HTTPX disables proxy inheritance and redirects; request/response sizes and elapsed time are bounded. Capabilities are explicit. These controls do not make a trusted operator's arbitrary endpoint configuration an SSRF-proof sandbox.
- Tool inputs have strict schemas, relative-path validation, allowlists, required permissions and file/count/byte limits. Stores are bound to one session. There are no shell, host filesystem, general network, arbitrary code or untrusted-container tools. Model output is never promoted to an elevated instruction role.
- Only compiled-in trusted evaluators run in process. Author criteria are bounded data, not module paths or Python code. Public problem projections exclude private configuration. Event evidence measures observable actions, not hidden reasoning or guaranteed human understanding.
- Trace payload retention is bounded to at most 90 days. Expired reads/writes fail closed; the worker or maintenance CLI purges payloads and writes minimal deletion metadata. Account erasure removes private solve data and revokes sessions, leaving an inactive pseudonymous ownership/audit tombstone. Audit records have a separate maximum 90-day retention.
- New persisted text scrubs the configured provider key and recognized sensitive fields/token patterns. Provider raw bodies, headers, URLs and internal exception details are omitted from participant errors. Internal diagnostics use controlled codes and operation IDs. Validation responses omit submitted input values. React renders user/model text as text.

## Reportable findings and limits

Authentication bypass, privilege escalation, cross-account access, CSRF, unsafe tool paths, resource-bound bypasses, stale-worker writes, evidence/retention inconsistencies, credential exposure and unsafe dependency/build behavior are meaningful findings. A localhost restriction does not excuse an application-boundary defect. Report realistic preconditions and affected paths; do not infer safety solely from tests or scanner silence.

Public deployment remains unsupported. MFA, password reset/recovery, verified identity, production TLS/proxy configuration, comprehensive request/global quotas, operational monitoring, backup erasure/export, encryption-at-rest and a secret vault are not implemented. Authentication rate limits do not constitute complete abuse protection. If every worker is down, physical cleanup and lease reconciliation wait for a worker or maintenance command; expired trace reads remain blocked. Unrecognized PII/secrets can remain in conversations or historical records. Do not use sensitive real participant data in this preview.

There is no secure untrusted-code sandbox, external evaluator runner or distributed Judge. The separate AI worker executes trusted runtime/tool code only. No complete tamper-proof evidence or reproducible external LLM replay is claimed. Native Windows build-path behavior and actual commercial LLM inference need separate verification.

## Reporting

GitHub Private Vulnerability Reporting is enabled. Use [Report a vulnerability](https://github.com/casing1/praxioj/security/advisories/new) to contact the maintainer privately. Include affected versions, prerequisites, impact and a minimal synthetic reproduction. Do not include live credentials, participant data or private submissions. Keep sensitive details out of public issues while assessed. Publication of Apache-2.0 source does not authorize public service deployment.
