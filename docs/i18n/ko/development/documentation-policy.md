# 문서·번역 정책

[English](../../../development/documentation-policy.md) · [문서 목차](../index.md)

## 목적과 상태

M6-A에 앞선 개발 관리 변경부터 적용하는 PraxiOJ의 재사용 가능한 문서 표준이다. 문서 관리 규칙이며 Runtime 수용 검증의 증거는 아니다. 완료된 제품 기준선은 M5다. M6-A/M6-B 추적 객체를 생성하는 것으로 해당 Milestone의 구현이 완료되지는 않는다.

## 원본과 언어

영어가 원본이며 한국어를 유지 번역 언어로 지원한다. 신규 주요 기술 문서와 실질적으로 변경한 핵심 문서는 같은 PR에 한국어 대응 문서를 포함한다. 양쪽 문서에 서로의 링크를 두고 [translations.json](../../../translations.json)에 등록한다. `docs/i18n/ko/` 아래 경로는 보통 원본 문서의 분류를 따른다. 프로젝트 README는 `docs/i18n/ko/README.md`, 문서 목차는 `docs/i18n/ko/index.md`를 사용한다.

코드 식별자, 환경변수, 명령어, API 경로, 프로토콜 값과 실제 기술 명칭은 바꾸지 않는다. 설명을 번역하고 보안 주장과 경고의 강도를 유지한다. 원본과 마찬가지로 구현된 동작, 설계 제안, 실제 실행한 검증을 구분한다.

M1–M5 문서를 한 번에 전부 번역할 필요는 없다. 번역하지 않은 과거 자료임을 밝히고, 더 넓은 번역은 별도 범위의 Issue로 관리한다. 영문 원본과 다른 한국어 설계를 조용히 도입하지 않는다. 일시적인 번역 지연이 있다면 해당 문서 쌍, 이유, 추적 Issue를 PR에 명시하고 동기화 완료를 주장하기 전에 해결한다.

## 필수 내용

신규 기술 문서에는 목적, 현재 상태, 요구사항·비목표, 컴포넌트 책임, 신뢰 경계, 호환성 영향, 수용 기준, 증거, 한계와 관련 Issue/PR/문서 링크를 쓴다. 실제 변경에 맞게 [템플릿](../index.md)을 조정한다. 설계 제안은 구현 증거가 아니며 빈 템플릿은 검증 보고서가 아니다.

검증 기록에는 테스트한 리비전과 환경, 명령과 실제 통과·실패·Skip 수, 실행하지 못한 경로, 보안 테스트, 최적화 검토와 GitHub 전달 결과를 기록한다. 성능 개선은 비교 가능한 Before/After 부하와 단위가 있을 때만 주장한다. 그렇지 않으면 **"reviewed; no justified optimization"**과 이유를 기록한다.

가능하면 저장소 상대 링크를 사용한다. 기존 문서 경로를 유지하고 이동이 필요하면 같은 변경에서 모든 참조를 수정한다. 새 문서는 [docs/README.md](../../../README.md)와 한국어 목차에 등록한다. 예시에 자격증명, 비공개 참가자 내용, 로컬 DB 파일이나 민감한 로그를 포함하지 않는다.

## README와 변경 이력 검토

모든 PR에서 루트 README와 CHANGELOG를 검토한다. 기능, 빠른 시작 명령, 설정, 지원 환경, 아키텍처 요약, 한계 또는 Milestone 상태가 바뀌면 README를 갱신한다. 바꾸지 않았다면 PR에 구체적인 이유를 쓴다. 한국어 대응 문서도 함께 검토한다.

[CHANGELOG.md](../../../../CHANGELOG.md)는 사용자에게 중요한 추가·변경·수정·보안 제어·실측 성능 변경·문서 변경을 기록한다. 미발행 작업은 `Unreleased` 아래에 두고 빈 분류는 생략할 수 있다. 실제 릴리스 시 Keep a Changelog 형식과 Semantic Versioning 원칙을 따르며 과거 Milestone에 존재하지 않는 릴리스·태그·날짜·버전을 만들지 않는다. 상세 내부 리팩터링은 모든 Commit을 복제하기보다 PR에서 설명한다.

## 검사와 검토

저장소의 결정적인 문서 검사를 실행하고 실제 출력을 확인한다. 외부 요청 없이 로컬 Markdown 대상·제목과 등록한 번역 쌍을 검사한다. 번역 품질, 기술적 사실, 외부 URL의 가용성이나 보안 주장을 입증하지는 못한다. 검토자는 실제 내용과 명령어를 변경된 구현과 대조한다.

```sh
python3 scripts/check-docs.py
python3 -m pytest -q tests/governance
```

병합 전에 상호 링크, 목차 등록, README/CHANGELOG 판단과 영문·국문의 일관성을 확인한다. PR에 정확한 테스트·CI 증거를 보존한다. Apache-2.0, 기여자 저작권과 필요한 제3자 고지를 유지한다. 독립 개인 프로젝트이므로 대학·연구실·기업의 소유나 공식 프로젝트임을 암시하지 않는다.
